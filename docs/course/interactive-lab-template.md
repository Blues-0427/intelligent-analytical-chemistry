# 互动教材范例与开发模板

第 1、2 章的互动案例是本课程的基准样例：不是在正文后附一个“测验”，而是把一个关键判断放进可感知的分析任务中。学生的选择必须改变即时反馈，并能回到正文中的测量假设、变量、失效条件和下一步行动。

## 范例入口

- [第 1 章：雨后河流异味——构成一条可辩护的测量闭环](#/docs/ch01)
- [第 2 章：数据急诊室——判断一批光谱能否进入模型](#/docs/ch02)

两个范例都只把进度保存在学生自己的浏览器中；不采集账号、姓名、答案或其他个人信息。

## 一个合格互动案例的最小结构

| 层次 | 必须回答的问题 | 第 1、2 章范例中的实现 |
|---|---|---|
| 情境 | 学生正在承担什么真实任务，结论影响谁？ | 应急检测负责人；数据质量审核员 |
| 概念目标 | 完成后必须理解哪一个基础关系？ | 测量闭环；数据对象与预处理边界 |
| 学生动作 | 学生必须作出什么可观察、可评价的选择？ | 选择采样/测量/信号/决策路径；隔离问题记录、选择元数据和数据划分 |
| 即时反馈 | 为什么这一步成立或不成立？ | 反馈连接到代表性、校准、信号归因、数据泄露与适用域 |
| 迁移 | 如何判断学生不是只记住答案？ | 更换样品、仪器或任务目标后，要求重新判断边界条件 |
| 证据 | 正文、图和引文怎样支持互动结论？ | 知识图谱、章节论述、可点击引文与年度更新卡 |

不要把“选择正确选项”本身当作学习目标。互动结束时，学生应能说明：**我作出这个选择，是因为它保留了哪一种化学信息，避免了哪一种测量或建模失效。**

## 复用方式

互动组件由 `assets/js/interactive-chapters.js` 统一加载。一个章节只需在 Markdown 合适位置加入占位元素：

```html
<section class="interactive-lab" data-lab="你的小组组件名称"></section>
```

维护组再在脚本中添加对应的渲染函数，并保持以下约定：

1. 使用原生 `button`、`label`、`fieldset` 等元素；不能仅靠鼠标悬停表达关键信息。
2. 每次选择应给出化学或测量学上的理由，而不是只有“对 / 错”。
3. 允许学生重置并重新推演；浏览器本地保存进度即可，不要上传个人答案。
4. 在手机上可用，且不依赖外部账号、付费服务或不可长期访问的第三方接口。
5. 互动中出现的关键事实应在正文、图或可点击引文中找到依据。

## 推荐的组内分工

| 角色 | 交付物 | 重点审查问题 |
|---|---|---|
| 情境设计者 | 任务简报、角色、行动后果 | 情境是否真实服务于本章概念，而非给概念换皮？ |
| 内容核验者 | 选项、反馈、引文与正文对应表 | 反馈是否准确表达假设、边界和可能的例外？ |
| 前端实现者 | 组件、移动端样式、键盘可达性 | 交互能否在无鼠标或小屏幕上完成？ |
| 图谱与评审者 | SVG 图、迁移题、测试记录 | 图是否解释了学生刚刚作出的判断？ |

## 提交前的验收清单

- [ ] 互动只服务于 1–2 个明确的知识目标，且正文中有对应解释。
- [ ] 至少包含一个真实分析任务、三次有意义的学生决策和一次迁移判断。
- [ ] 错误选项也有具体反馈，解释它在什么条件下会造成偏差或失效。
- [ ] 新增或修订了一幅可编辑 SVG 基础知识图，并在图旁解释变量、箭头和边界。
- [ ] 前沿更新、年度课件、传承题与可点击引文均已在章节末尾归档。
- [ ] 通过键盘 Tab、手机窄屏和“重置后重做”三项自测。

> 互动内容是教材的一部分。它也需要像公式、代码和图谱一样被同行复核，并在下一届学生的维护中留下可追踪的改进记录。
